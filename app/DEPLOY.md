# Compass — запуск и деплой

## Локально

```bash
npm install
npx prisma generate
npm run dev
```

Открыть http://localhost:3000. Демо-аккаунт: `student@test.local` / `hackathon2026`.

**Важно:** не запускать `next build`, пока работает `npm run dev` — сборка перезапишет
`.next` под живым процессом, и страницы начнут отдаваться без стилей. Если это
случилось: остановить сервер, удалить `.next`, поднять заново.

## Переменные окружения

`.env.local` (и `.env` — его читает Prisma CLI):

```
DATABASE_URL="file:./prisma/dev.db"
AUTH_SECRET="<openssl rand -base64 32>"
OPENAI_API_KEY=sk-proj-...
OPENAI_MODEL=gpt-4o-mini      # интервью, разбор увлечений, объяснения
OPENAI_CHAT_MODEL=gpt-4o      # советник
```

Без `OPENAI_API_KEY` приложение не падает: интервью переходит на резервные вопросы,
разбор увлечений отдаёт кешированные тайтлы, объяснения не генерируются. Всё
остальное — расчёт совпадений, рейтинг, skills gap, маршрут, подбор университетов —
работает полностью, потому что считается детерминированно.

## Тесты

```bash
npm test
```

Три прогона: целостность данных, 64 сквозные проверки по HTTP, проверка
персонализации на двух противоположных профилях.

## Особенность этой машины

Антивирус перехватывает TLS, и Node не доверяет его сертификатам. Поэтому:

- скрипты `dev` и `start` запускают Node с флагом `--use-system-ca`;
- шрифты **самохостятся** в `public/fonts`, `next/font/google` не используется —
  он молча падал и подставлял системные шрифты.

На обычной машине оба обхода безвредны.

## Деплой

### Подготовленная конфигурация Vercel

Проект: `eye172/compass-impact`. База: Neon `compass-db`, бесплатный тариф, Frankfurt.
`vercel.json` запускает `scripts/vercel-build.mjs`: он создаёт PostgreSQL-схему
из локальной схемы и генерирует production-клиент Prisma. Локальная схема остаётся SQLite.
Переменные production настроены в Vercel, секреты не хранить в git.

Документы до 4 МБ сохраняются в базе, скачивание `/api/documents/[id]/file`
проверяет авторизацию и владельца. Локальные старые файлы поддерживаются проверкой
документов, но не переносятся на сервер автоматически.

Для повторной публикации из `app`: `vercel deploy --prod`.
Схему базы обновлять отдельно, до деплоя, без сброса базы и без `--accept-data-loss`.
В облако перенесён каталог вузов, программ, стипендий и дедлайнов, но не локальные
пользователи и переписки. Регистрация создаёт новые постоянные аккаунты.

### Исходная локальная архитектура

Приложение — обычный Next.js 15, но **на SQLite с файлом внутри проекта**. Для
демо и для локального прогона этого достаточно. Для настоящего деплоя нужно
поменять базу:

1. В `prisma/schema.prisma` заменить `provider = "sqlite"` на `"postgresql"`.
2. Завести Postgres (Neon, Supabase, Vercel Postgres) и положить строку в `DATABASE_URL`.
3. `npx prisma migrate deploy`, затем засеять университеты: `npm run db:seed`.
4. Выложить на Vercel: `AUTH_SECRET`, `OPENAI_API_KEY`, `DATABASE_URL` — в переменные проекта.

Пока это не сделано, на Vercel приложение поднимется, но данные будут теряться:
файловая система там эфемерная. Это единственное, что отделяет проект от продакшна.
